# Migrations that expo/ship.sh applies, in this order, on every release.
# One file per line (paths relative to expo/supabase/). Blank lines and # comments are ignored.
#
# Every file below is IDEMPOTENT (safe to run again and again) and none of them defines an older version of something a
# later file defines. migration-known-connections.sql comes after every file that creates trial_* functions (it revokes client
# access to them) and builds the known_connections view (phone, email, friends, hide list); migration-friends-messages.sql comes
# before it. migration-stranger-only.sql redefines the feed, the trial rules and sharing on top of all of them and revokes its own
# internals itself. migration-spotlight.sql: Spotlight tables and RPCs, and the feed once more (the stranger-only feed plus the Spotlight
# lead). migration-harassment.sql: the word filter, unwanted-contact flags, creator controls and the review queue (triggers on
# chat_messages, posts and likes). migration-recovery.sql is the LAST file: Recovery Boost (offers, the boost, the owner's
# confirmation in admin_report_resolve) and the feed once more.
#
# migration-live-snapshot.sql (written by scripts/dump-live-definitions.mjs from the LIVE database, listed here right before
# migration-known-connections.sql) is the record of what was applied by hand: get_feed_engine, expire_posts, chat_can_send_post,
# chat_post_available and the compat views conversations / messages. It is applied AFTER the older files that define earlier versions
# of the same objects, so a release can never put an older version back. Change those objects only in a NEWER migration ordered after it.
#
# Keep this file up to date whenever a migration is added or changed.
